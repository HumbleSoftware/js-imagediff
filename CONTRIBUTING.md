# Contributing

See the Development section of the [README](README.md) for local setup and scripts.

## Commit messages and PR titles

Commit messages and PR titles follow [Conventional Commits](https://www.conventionalcommits.org/): `<type>: <summary>`, lowercase, imperative, no trailing period. Add a scope (`fix(cli): ...`) only when it helps, and mark breaking changes with `!` (`feat!: ...`).

Types: `feat`, `fix`, `docs`, `test`, `ci`, `build`, `refactor`, `chore`.

Examples from this repo:

```
test: replace Karma/PhantomJS with Playwright
ci: add a dev container
chore: declare the Node version for local development
docs: trim local setup to the essentials
```

## Build outputs

`imagediff.js` and `imagediff.min.js` are generated by `npm run build` and committed for releases. Rebuild and commit them only when preparing a release; ordinary PRs change `js/imagediff.js` and leave the built files alone. `npm test` runs against the source, including the CLI, so nothing needs rebuilding to test a change.

## Releasing

On the release PR, after `npm run build` and committing the build outputs, run:

```sh
npm run test:release
```

It rebuilds, runs `npm test` against the built `imagediff.js` and `imagediff.min.js` (through `require` in Node and in a page, along with the CLI specs), and then fails if the fresh build differs from the committed build outputs. Publish only once it passes.
